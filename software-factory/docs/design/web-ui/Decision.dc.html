0004 Agent messaging over NATS

Move the agents' chatter off GitHub to a NATS hub; keep on GitHub what the PR gate or the owner must see.

PRD

Context

All roles share one GitHub account, and its 5,000 REST calls an hour run out in minutes: on 31 Oct nine loops used about 2,300 calls in the first 9 minutes after the reset, then sat idle (#371). Most of those calls are agents talking to each other through comments and labels.

The owner's direction (31 Oct): move the agents' chatter off GitHub to NATS, and keep on GitHub what the PR gate or the owner must see.

Decision

  1. Messaging is a setting, behind decision 0003's messaging port: agents send messages through GitHub (the default) or through NATS.
  2. One hub, a leaf server on each machine, in Docker. dev-pc runs the hub with JetStream; the Mac runs a leaf that connects over Tailscale.
  3. One credential per agent. An agent may publish only as itself.
  4. When the hub can't be reached, fall back to GitHub; don't wait.
Moves to NATS Stays on GitHub
{{m.a}}{{m.b}}

Consequences

  • Agents stop re-reading every comment to find claims and wake-ups; GitHub calls go to what the gate and the owner need.
  • Nothing that arrives over NATS changes what may merge. The PR gate reads only GitHub.
  • Each machine needs Docker. The health check confirms the server answers and that publishing as another agent is refused.
  • Said plainly: agents on one machine share one OS user, so per-agent keys stop mistakes, not a hostile agent on that user.
  • Amends PRD D10 ("GitHub is the state and the transport") and D13.
