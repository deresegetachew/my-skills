# Business fact sheet (section A)

Fill this in with the owner before the first design round. Keep it on one page, and have the owner sign each line with a name and date. Every claim on the page must trace to a line here or to a PRD story. When a line changes, the page changes in the same round.

| Topic | The fact | Source (owner + date, or PRD story) |
|---|---|---|
| The real story | The customer case the product fixes, in 3 lines, with a link to the thread or review | |
| What is sold | Each stage of the customer's journey the product covers (for example sell, build, after-sales) | |
| Who buys | The kinds of customer company, and the roles inside them that can say no | |
| Who uses it | The end customer, and what they must never be asked for (an app, an account…) | |
| Price | The number on the price card, what one unit is, the cap, what is above it | |
| Cost per unit | What one use costs us (hosting, model calls), and where it is served from | |
| Built now | The features live at launch | |
| Planned | The features with a PRD story ("coming later") | |
| Not planned | The things we will say no to (integrations, custom domains…) | |
| Data | What is stored, for how long, who is responsible, what is deleted and when | |
| Promises | Guarantees (link lifetime, uptime), liability, what happens if the customer stops paying or we close | |
| Headline | The owner's line, and any line under it | |
| Words never used | For example a word that belittles the buyer, technology names, provider names | |
| Design → product | Whether the design page is the source and gets ported, or the design is done in the app | |
